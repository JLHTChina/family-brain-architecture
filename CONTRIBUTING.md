# Contributing

Thanks for your interest. This is a public architecture reference; the private deployment is not part of this repository.

## Ground rules

- Do not submit secrets, tokens, credentials, private inventory, personal data, school data or customer data.
- Do not submit code or diagrams you do not have the right to publish.
- Keep examples vendor-neutral and sanitized.
- Use the Apache-2.0 license for code and CC BY 4.0 for documentation by submitting a contribution.
- Sign off your commits (DCO) with `git commit -s`.

## Pull requests

1. Open an issue for significant changes.
2. Keep changes focused; one concern per PR.
3. Update docs and diagrams when behavior or policy changes.
4. Run a secret scan before pushing.
5. Describe the security impact and the human-approval implications.

## Style

- Prefer clear, testable statements over marketing language.
- Mark assumptions, limits and failure modes explicitly.
- Use Mermaid for diagrams when possible.
- Do not include real hostnames, IPs, MAC addresses, serial numbers, order IDs or personal names.
